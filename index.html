What I have been building, silicon first

Most of my time goes into four things. An LLM inference accelerator for models that do not fit on one die. A GPU-accelerated RTL-to-routing flow. RISC-V cores. And AI agents that verify hardware, plus the benchmark that scores them.

I work from the workload down. Pick the real model, work out what is physically possible, then design the chip. Not the other way round.

02

GPU-accelerated EDA

Speed up the stages where the maths is dense and parallel. Partition the ones where it is not. Working out which is which is most of the job.

gpu-eda

private

A GPU-accelerated RTL-to-routing flow. I tensorized static timing and global routing. Synthesis and detailed routing I partition instead, because irregular graph rewriting and sequential conflict resolution do not become parallel just because you want them to.

Timing
levelize once with Kahn, then arrival time is gather + scatter_reduce(amax) per level and required time is the same with amin. A 100k-node, 392k-arc graph runs in about 18 ms on CPU, and that op shape is what saturates a GPU
Routing
both L-shape candidates for every net in the design costed at once, using cumsum prefix tables over the congestion map. PathFinder handles rip-up
Placement
DREAMPlace, unmodified. It is already PyTorch and CUDA native, so there was nothing to add
Size
105 commits
PyTorchCUDAYosysDREAMPlaceOpenTimer lineage
For Hugging FaceThis is ML systems thinking applied to EDA. Seeing that static timing is a levelized scatter-reduce, and that global routing is a batched prefix-sum problem, is the same kind of reframing that turns attention into a kernel.

chipgpt

private

An agentic RTL and DV verification co-worker. It reads the spec, scans real public RTL, finds the bug, writes an SVA and a directed test, then emits a bug card and a traceability row. Each bug carries a badge saying how it was proven, because picking the right proof for each bug is the actual work.

Real bugs

What I would want to talk about

Three habits run through all of it.

Start from the workload. The accelerator starts from gpt-oss-120b and a feasibility envelope, not from whichever FPGA board was on the desk. It is the same idea as profiling before you optimise, except the answer comes out as a package and an HBM stack.

Be honest about what is parallel. gpu-eda speeds up static timing and global routing, and leaves detailed routing alone, because detailed routing is sequential conflict resolution and pretending otherwise wastes a year.

Build the scorer before the agent. CoreEval is a benchmark and an RL environment for hardware verification, where formal proof and simulation give you a real answer instead of a rater's opinion. The same instinct shows up in the research pipeline, where every stage has a gate that can fail it.

I would like to do this for the open source inference layer.
